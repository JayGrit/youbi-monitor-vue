# 任务流程图布局约定

适用于 `src/components/monitor/TaskProgressGraph.vue`。新增阶段、拆分阶段或调整 DAG 分支时，按本文检查流程图的节点位置和文案。

## 数据从哪里来

- `progress.routeNodes` 和 `progress.routeEdges` 是图的输入。监控后端优先读取 `distributor_task_route_nodes`、`distributor_task_route_edges` 中的任务快照。
- 节点标题来自 `distributor_type_stages.remark`；运行状态来自 `distributor_task_stages`。代码路由变更后，还须核对线上阶段配置和已有任务快照，否则图中可能缺节点。
- 图只呈现实际依赖。文档分支目前为 `publisher.article_document_generation`（准备双语文稿）→ `asseter.article_document_render`（双语文档）；它与音频、封面和视频分支并行。

## 布局规则

1. 用依赖深度决定列号：根节点为第 1 列，子节点在最深父节点右侧一列。不要为某个阶段额外加列偏移，否则新增子节点时可能与父节点重叠。
2. 按分支宽度、下游长度和原始节点顺序分配纵向区间，保持同一分支尽量接近。多父节点汇合时，取其入边区间的整体范围作为期望位置。
3. 同一列内按期望位置排序，依次分配独立网格行；后一个节点至少在前一个节点下一行。最终行数取实际占用行数，避免同列节点在汇合或嵌套分支中盖住彼此。
4. 节点位置确定后，再按实际 DOM 边界画 SVG 连线。单父节点使用折线；多父节点使用汇合干线。窗口尺寸变化时重新计算连线。

布局实现见 `TaskProgressGraph.vue` 的 `layout` 计算属性；行高、列宽和间距见 `src/styles/monitor.css` 中的 `.task-dag-grid`。

## 文案与视觉检查

- 节点标题写当前阶段的**动作或产物**，保持短句。准备材料与生成资产应是两个节点；例如“准备双语文稿”→“双语文档”。长说明放在阶段详情中，避免图上截断。
- 写入中文 `remark` 时使用 UTF-8 数据库连接，并读回核对。乱码不会由前端布局修复。
- 用真实任务的进度数据在本地渲染，至少检查：父子节点不重叠、同列节点不重叠、连线能辨认分叉与汇合、标题没有乱码、窄屏回退布局可读。
- 本次视觉基准使用 `podcast-58` 的真实 `routeNodes`/`routeEdges`。新增类似并行分支时，优先找包含该分支和汇合点的真实任务复查。

## 本次问题与修正

此前文档准备节点有固定的右移一列规则。增加 asseter 文档节点后，两个节点占了同一列、同一位置；分支区间还使“最终封面”和“识别对话”在同列相互遮挡。现在统一按依赖深度排布，并对每列做占位避让。数据库中的新阶段标题也改为简短、可读的中文。
